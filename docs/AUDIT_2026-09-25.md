# JustNews audit: 2026-09-25

**Scope:**
- The web app on a production build (`next build && next start`), against the
  local API and database.
- Lab: 13 routes at 1440×900 and 390×844, measured in Chromium. Per route: TTFB,
  LCP, CLS, requests, bytes by type, console errors, axe (WCAG 2.1 AA),
  horizontal overflow, headings, title and description.
- One batched screenshot pass.
- Reading the code for structure, security and data honesty.

**Not covered:**
- Signed-in flows (no test account).
- Production latency: it has been measured before, see ADR 0014.
- Real multi-source clusters: the local encoder produces almost none.

Severity:
- **P0**: broken for real readers.
- **P1**: a real flaw, fix soon.
- **P2**: debt or polish.

---

## P0: broken

1. **"Sign in" is invisible in the sidebar.**
   - Leftover icon-rail CSS styles `.account-menu__email` as a hover tooltip:
     `position: absolute; opacity: 0`.
   - Inside the new sidebar that hides the only sign-in control on desktop.
     Signed out, it is an empty bordered box with an icon. Signed in, the
     reader's email is invisible too.
   - Measured: `opacity=0 pos=absolute` on "Sign in".
2. **Followed stories have nowhere to be seen.**
   - Following a story still works, and so do its "N new reports since you
     looked" counts (migration 0018, the API, the story page button).
   - But the list lived on My Desk, which is now a redirect.
   - A reader can follow a story and never find it again.
3. **A hydration error on `/hi`, at both widths.**
   - React #418: the client rendered a text node the server did not.
   - React throws away the server HTML for that subtree and re-renders it,
     which costs work and flicker.
   - Only the Hindi front page shows it. The cause needs a dev-mode
     reproduction.
4. **Aquila scrolls sideways on phones.**
   - The controls row (arrows, folio, Contents, Full screen) is 422px wide in
     a 390px viewport.
   - The Full screen button was added without letting the row wrap.

## P1: technical

5. **Images are the page weight.**
   - Discover downloads 1.5 MB of images on desktop (Top: the same; `/hi`:
     1.8 MB). The largest is 652 KB, for a card about 400px wide.
   - Every image is the publisher's original, hotlinked with `unoptimized`.
     Nothing is resized, and nothing is served as AVIF or WebP.
   - Search pulls 1.4 MB the same way.
6. **Fonts cost 257 KB on every page, 492 KB on Hindi pages.**
   - There are four families. Cormorant Garamond ships 4 weights × 2 styles.
   - Both Devanagari families load on `/hi`.
   - Two or three weights would do.
7. **Every language's strings reach every reader.**
   - `lib/i18n.ts` holds en, es and hi in one module, imported by client
     components.
   - The result is a 98 KB chunk (25 KB gzipped) on every page, roughly two
     thirds of which is for languages the reader is not using.
8. **Aquila shifts after load on desktop (CLS 0.133, above the 0.1
   "good" line).**
   - The sheet renders unscaled.
   - `useLayoutEffect` then scales it. That runs only after hydration, so the
     first paint is the wrong size.
9. **No security headers beyond the basics.**
   - There is no Content-Security-Policy (the app hotlinks images and favicons
     from any host, so it needs one to limit what can load).
   - There is no Permissions-Policy.
   - There is no HSTS from the app. Vercel adds HSTS at the edge, but the
     local `next start` and any other host do not.
10. **Preference cookies lack `Secure`.**
    - `jn_sid`, `jn_sidebar`, `jn_rail`, `jn_weather` and `jn_temp_unit` are
      set without it.
    - Harmless over HTTPS-only Vercel, but not stated. `jn_sid` is also
      readable by scripts, which it does not need to be.
11. **Production still pays the ocean.**
    - The region move and Upstash are deferred (ADR 0014).
    - The Redis cache is written but off in production until Upstash is
      configured. Every shared read still goes Oregon → Tokyo.
12. **Next's own routes have no rate limit.**
    - The API is limited, but these are not: `/api/discover`,
      `/api/widgets/weather`, `/api/widgets/places` and `/api/click`.
    - Weather and places are cached, which blunts it. The rest proxy straight
      to the API or to Open-Meteo.
13. **Trending Companies can be wrong by construction.**
    - It matches on whole-word names, and several are ordinary words or
      groups: "Shell", "BP", "Tata", "Reliance", "Meta", "Apple", "Visa Inc".
    - A headline about a bomb shell, or a Tata Steel story counted as "Tata
      Group", both land.
    - It is labelled as mentions, which is honest, but there is no check that
      the article is about the company.
14. **The build depends on Google Fonts being reachable.**
    - `next/font/google` downloads the fonts at build time. CI already failed
      once when Google served an unexpected response.

## P1: design and UX

15. **Top and For You are the same page for most visitors.**
    - A signed-out reader who has not picked interests gets Top under the For
      You tab. Measured: identical bytes and height.
    - Two tabs that show the same thing read as broken.
16. **Two topic experiences.**
    - The Topics menu on Discover swaps the feed in place.
    - `/desk/{id}` (linked from articles' "Filed under", search suggestions and
      Aquila) is the old Understand/Latest page. It has different typography,
      its own tabs, "0 stories", and long raw IPTC labels in Related topics
      ("Conflict, war and peace") where the rest of the product says
      "Conflict".
17. **The pages Discover didn't touch look like a different product.**
    - The story page opens with a full-width photograph that fills the screen,
      and a "Covered by 1 source" line beside an "English 2" chip that
      contradicts it.
    - The article, source, topic and search pages use the older list style,
      not Discover's cards.
    - The sidebar is shared, but the pages under it are not.
18. **Phones get none of the rail.**
    - Below 75rem the widgets are hidden: no weather, markets or companies.
    - That was deliberate (an infinite feed hides anything below it), but it
      means half the new feature does not exist on mobile.
19. **The phone drawer does not manage focus.**
    - Opening it leaves focus on the menu button, so Tab walks the page behind
      the scrim, not the drawer.
    - Closing it does not return focus to the button.
20. **Discover's views are indistinguishable to browsers and search.**
    - Every view is titled "JustNews". A topic view is not
      "Politics · JustNews".
    - Most pages share the site-wide description. The description is written
      as a `<meta>` in the body (so it flushes early) rather than through
      metadata.
21. **Aquila's own navigation is stale.**
    - Its sidebar still offers Home and My Desk.
    - "My Desk" is now a redirect to Discover, and "Home" is called Discover
      everywhere else.
22. **The sitemap lists a redirect.** `/{locale}/desk` is in `sitemap.ts` but
    permanently redirects. It should list Discover's views instead.

## P2: debt and polish

23. **`globals.css` is 7,248 lines in one file.**
    - About 60 of its selectors style nothing: the old rail, masthead, site
      footer, Home tiers, My Desk tiles, the brief and trending rails.
    - That is part of the 107 KB stylesheet on every page, and the cause of
      bug 1.
24. **Dead strings and components.**
    - About 62 `desk.*` strings remain in each of the three locales. Most
      served My Desk; which of them `/desk/{id}` still uses was not checked.
    - `DeskRail` still serves `/desk/{id}`.
    - `components/ArticleCard.tsx` (440 lines, 8 variants) now serves only the
      old pages.
25. **Collapsed-sidebar tooltips go stale.** Link `title`s are server-rendered
    from the cookie, so toggling on the client leaves them wrong until the next
    page load.
26. **`/en/saved` has two h1s** when signed out: the page's and the
    sign-in card's.
27. **Signed-out pages are dead ends.**
    - Saved and History show only "Sign in to see this", with no preview of
      what a reader would get.
    - The Saved heart on every card sends a signed-out reader to the login
      page with no explanation.
28. **The formatting of new files is inconsistent.** One component is
    Prettier'd at 80 columns and the rest at about 100. There is no
    formatter config or format check for the web app.
29. **Test gaps.**
    - No signed-in e2e: 3 specs are skipped.
    - No test of the drawer, the customize panel's reorder, infinite scroll,
      or the Topics menu.
    - One flaky, order-dependent backend test (`test_follows_api.py`) since the
      fifth pass.
30. **Open-Meteo's free tier is for non-commercial use.** Fine now; it needs a
    paid plan or another provider before any commercial launch.

---

## What held up

- **axe:** no WCAG 2.1 AA violations on any of the 13 routes (desktop), or on
  Discover at phone width.
- **No console errors** anywhere except `/hi`.
- **Local performance:**
  - Discover LCP 0.3s desktop, 0.5–0.7s phone.
  - TTFB under 100ms.
  - CLS 0 on everything but Aquila (and 0.02–0.03 on search).
- **No horizontal overflow** anywhere except Aquila on phones.
- **The web tier's write routes all check origin.** No open redirects: the
  auth callback and consent return are both tested.
- **Personal feeds and consented Aquila reads are never cached,** so logged
  propensities stay true.

## Suggested order

1. **The P0s:** sidebar Sign in, a home for followed stories (a "Following"
   item in the sidebar), the `/hi` hydration error, Aquila's controls on
   phones.
2. **Weight:** responsive images through an image proxy or resizing CDN, font
   weights down to what is used, and per-locale message bundles.
3. **One visual language:** rebuild the story, article, source and topic pages
   in Discover's card system, and retire `/desk/{id}` for the in-place topic
   view.
4. **Security headers, cookie flags,** and rate limits on the Next routes.
5. **Deferred infrastructure:** the region move and Upstash (ADR 0014).
